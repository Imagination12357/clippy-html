# Report Search Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Search lint names, file paths, diagnostic messages and categories with
the statically analyzed rustdoc interface and a report-owned local engine.

**Architecture:** Generate a safe JavaScript index from Report/SourceFile/PageMap.
Keep pure matching separate from DOM behavior; reuse pinned rustdoc CSS and DOM
components for in-place search. Validate links/assets before publication.

**Tech Stack:** Existing Rust/serde_json/Askama, classic JavaScript, Node test runner.

**Spec:** ../specs/2026-11-07-search-design.md

## Global Constraints

- Rust 1.94; no new production dependency or frontend build pipeline.
- file:// and static-subpath friendly: no runtime fetch/module/CDN dependency.
- Preserve deterministic finding IDs, existing sidebar and JS-free navigation.
- Text-only dynamic rendering; PageMap-owned hrefs; existing license structure.
- Pinned rustdoc 1.97.1 classes/styles; four report-specific tabs only.
- Existing codex/search checkout, no merge/push; autonomous verified commits approved.

## Review Focus

- Malicious messages/query/file text must never become executable HTML or URLs.
- Nested/Unicode source paths must resolve from source, category and lint pages.
- Deep-query load, Back/Forward and unavailable history must keep search usable.
- IME/editable targets and keyboard close must preserve text entry and focus.
- Missing JavaScript/data must leave ordinary document navigation available.

### Task 1: Search index and publication contract

**Files:** create src/render/search.rs; modify src/render/mod.rs, pages.rs,
assets.rs; extend tests/integration.rs as appropriate.

**Interfaces:** `search::write_index(report, sources, pages, destination) ->
Result<(), String>` emits static.files/search-index.js; `search::read_hrefs(root)
-> Result<Vec<String>, String>` returns destinations for publication validation.
Serialized entries use kind/name/context/description/href fields.

- [ ] Write tests for four kinds, one finding per deduplicated report finding,
  escaped script-sensitive text, primary path context and child messages.
- [ ] Watch tests fail, implement deterministic index serialization using PageMap.
- [ ] Add failing tests for absent/nonlocal script resources and bad index anchors;
  extend validate_report to check both new resource and index destinations.
- [ ] Run targeted Rust tests and commit the independently verified index change.

### Task 2: Pure local matching

**Files:** create assets/search-engine.js, tests/search-engine.test.cjs;
register static asset in src/render/assets.rs.

**Interfaces:** globalThis.ClippyHtmlSearch.createIndex(entries) returns
preprocessed entries; `.query(index, text)` returns four arrays sorted by rank.
The DOM layer applies the 100-row display cap while keeping totals.

- [ ] Write Node tests for exact/prefix/substring/context ranking, AND terms,
  NFC/case/Unicode, empty/no-match and deterministic ties.
- [ ] Watch tests fail; implement pure matching with no DOM/global side effects
  other than the named API. Do not parse rustdoc API query syntax.
- [ ] Run `node --test tests/search-engine.test.cjs`; commit when green.

### Task 3: Pinned rustdoc interaction and end-to-end validation

**Files:** create assets/search.js and assets/vendor/rustdoc/SEARCH.md;
modify templates/base.html, assets/clippy-html.css, src/render/assets.rs,
THIRD-PARTY-NOTICES.md, templates/licenses.html, vendor UPSTREAM.md;
update README.md, ROADMAP.md and add docs/validation/2026-11-07-search.md.

**Interfaces:** ordered deferred classic scripts index → engine → UI, using
data-report-root for page-relative resolution. Hidden toolbar becomes available
only after initialization. Search query URL parameter is `search`.
