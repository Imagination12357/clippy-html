# CI Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans for inline implementation and one final fresh-context review.

**Goal:** Test supported platforms and publish a successful online self-report to GitHub Pages.

**Architecture:** One Actions workflow runs stable tests on three OSes, a Linux MSRV compile check, and Linux quality/DOM checks. PR dogfooding has read-only permissions; main combines report generation and Pages publication in one gated job. A small Bash helper preserves installation/report logs and command failure status.

**Tech Stack:** GitHub Actions, Rust stable/1.88.0, Node 24, npm lockfile, Bash.

**Spec:** User-approved CI scope in this conversation, recorded below.

## Global constraints

- Stable tests: Windows, Linux and macOS; Linux Rust 1.88.0 checks all targets with the lockfile.
- Quality: fmt, strict Clippy and existing Node/DOM tests. Node remains test-only.
- Generate one online report with the installed current tool and pedantic warnings; no offline report.
- PR: artifact only, no Pages/OIDC permissions. Main/manual main: deploy only after all checks and report generation succeed.
- Preserve available report/log artifacts on failure without swallowing the exit status. Use fresh output outside the Rust cache.
- Pin external Actions to verified release commits. Do not push or change remote repository settings.
- Work and commit on local main as explicitly authorized.

## Review focus

- A failed install/Clippy process must fail the job and retain available logs/report.
- A cached or pre-existing report must never be published as a new success.
- PR source must not execute in a job with Pages/OIDC permissions.
- Matrix subprocesses must use the selected toolchain, including Clippy fixtures.
- Failed prerequisite checks must leave the last successful Pages deployment intact.
