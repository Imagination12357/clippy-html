# Clippy HTML Phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 실행 방식은 사용자가 선택한다. 계획 작성은 구현 승인이 아니다.

**Goal:** 실제 Clippy 결과로 rustdoc CSS 기반 홈·lint·소스 보고서를 생성하고, Windows에서 로컬 탐색과 실패 상태 보존을 검증한다.

**Architecture:** 단일 Cargo package 안에서 CLI, Cargo 수집, 진단 정규화, 소스 로드, HTML 생성, 출력 갱신을 분리한다. renderer는 Cargo를 실행하지 않는다. 동기 실행과 stderr 소비 thread를 사용한다.

**Tech Stack:** Rust 2024, std::process/std::thread, clap, cargo_metadata, serde/serde_json, Askama, BLAKE3, tempfile, webbrowser/url. 프런트엔드 빌드 도구는 없다.

**Spec:** ../specs/2026-10-27-clippy-html-design.md 및 저장소 루트 DETAILS.md. 구현자는 두 문서를 모두 읽는다.

## Global Constraints

- 단일 Cargo package, Rust 2024 edition을 유지한다.
- 원본 소스와 Cargo 설정은 수정하지 않는다. Cargo 자체의 빌드 산출물과 lockfile 동작은 허용한다.
- rustdoc CSS를 직접 재사용하며, 첫 보고서부터 해당 스타일을 적용한다.
- 당장 폰트는 시스템 글꼴을 사용한다.
- 기본 결과물은 서버 없는 정적 멀티페이지 HTML이다. 진단마다 별도 페이지는 만들지 않는다.
- Phase 1은 --output, --open, --help, --version을 지원한다. --metadata는 Phase 3에서 추가한다.
- 모든 내부 링크는 상대경로를 사용한다. 기본 탐색은 JavaScript 없이 작동한다.
- Windows 11 / PowerShell, Linux, macOS를 지원 대상으로 설계한다. 현지 검증만으로 다른 OS의 통과를 주장하지 않는다.
- source/message/path는 신뢰하지 않는다. escaping과 경로 경계는 Phase 1부터 검증한다.
- 실행 실패를 성공으로 처리하지 않는다. Clippy 실패에도 가능한 보고서를 생성한다.
- 제품 변경·설치·빌드·테스트·브라우저 열기는 구현 승인 이후 수행한다. 커밋·브랜치 변경도 사용자 승인 범위에서만 수행한다.

## Review Focus

1. 캐시에 있는 무진단 target도 정상 검사로 표시한다. build-finished와 artifact를 확인한다. Task 4/8.
2. severity 또는 복합 suggestion이 다른 같은 위치의 진단은 병합하지 않는다. Task 3.
3. Unicode/CRLF와 현재 파일 불일치에서 잘못된 강조나 diff를 만들지 않는다. Task 5.
4. namespace/대소문자 충돌과 같은 줄의 복수 finding이 링크를 깨뜨리지 않는다. Task 5/6.
5. 출력 교체 실패와 동시 실행에서 정상 보고서나 사용자의 일반 폴더를 잃지 않는다. Task 7.

## 기술 선택

아래는 설계자의 선택이며 사용자가 특정 라이브러리를 요청한 것으로 해석하지 않는다.

- 최초 지원 하한 후보는 Rust 1.94이다. Task 1에서 실제 확인하기 전에는 검증된 MSRV라고 문서화하지 않는다. 미설치 toolchain은 사용자 권한 범위에서 처리하고 미검증 사실을 기록한다.
- 초기 버전 요구사항: clap 4.6.7(derive), cargo_metadata 0.23.1, serde 1(derive), serde_json 1, askama 0.16.1, blake3 1.8.7, tempfile 3.27.0, webbrowser 1.2.5, url 2.
- 의존성은 필요한 Task에서 추가하고 Cargo.lock을 갱신한 뒤 --locked로 검증한다. 이유 없는 버전 갱신은 하지 않는다.
- Askama HTML 자동 escaping을 사용한다. 원본 데이터에 safe 필터를 적용하지 않는다.
- BLAKE3 전체 32-byte hex를 ID 기본값으로 쓰고 충돌 시 canonical 내용 비교와 정렬 suffix로 구별한다.
- CSS 기준은 Rust 1.90.0이다. Task 6에서 공식 tag의 전체 commit SHA를 확인·기록한 뒤 해당 SHA URL로 자산을 가져온다.
- stderr와 비구조화 stdout 보관 상한은 각각 1 MiB이다. 이후에도 스트림 소비를 계속하고 생략 여부를 표시한다.
- 강제 실패는 private helper 또는 test-only 인자로 주입한다. 운영 CLI에 테스트 옵션을 추가하지 않는다.

## 공통 모델

경로는 PathBuf, 프로세스 인자는 OsString을 유지한다. 독립 모델에는 cargo_metadata 타입을 노출하지 않는다.

- RunOptions: output(Option<PathBuf>), open(bool), clippy_args(Vec<OsString>).
- CargoContext: cwd(PathBuf), cargo_exe(OsString), metadata_args(Vec<OsString>), target_dir_override(Option<PathBuf>).
- CliAction: Run(RunOptions) / Display{text, exit_code}. CLI 오류 종료 코드는 2.
- FindingId(String), SourceKey(PathBuf): 진단과 소스 식별자.
- RunState: Success / Failed{code: Option<i32>} / NotStarted. CollectionState: Complete / Incomplete.
- Origin: Clippy / Compiler / General. Level: Error / Warning / Note / Help / Other(String).
- Applicability: MachineApplicable / MaybeIncorrect / HasPlaceholders / Unspecified / Other(String).
- TargetInfo: name, kinds(Vec<String>), source(PathBuf).
- Span: source(SourceKey), byte_start/end(u64), line_start/end 및 column_start/end(usize), primary, label, snippet(Vec<SnippetLine>), expansion(Option<Box<Expansion>>).
- SnippetLine: text, highlight_start/end. Expansion: call_site(Box<Span>), macro_name, definition_site(Option<Box<Span>>).
- Note: level, message, spans(Vec<Span>), children(Vec<Note>).
- Replacement: span, text, applicability. Suggestion: message, child_path(Vec<usize>), replacements(Vec<Replacement>).
- Finding: id, package_id, targets, origin, code(Option<String>), level, category(Option<String>), message, spans, children, suggestions, rendered(Option<String>).
- PackageInfo: id, name, manifest(PathBuf), workspace_member. ProjectInfo: workspace_root, target_dir, packages(Vec<PackageInfo>).
- Execution: state, collection, requested_args, observed_packages, observed_targets, stderr, stderr_truncated, text_stdout, stdout_truncated, issues(Vec<String>).
- Report: project(ProjectInfo), execution(Execution), raw_count(usize), findings(Vec<Finding>).

필요한 derive만 추가한다. fingerprint용 Serialize 구조는 dedup 안에 두고 OS 인자를 JSON화하려고 Report 전체에 Serialize를 강제하지 않는다.
