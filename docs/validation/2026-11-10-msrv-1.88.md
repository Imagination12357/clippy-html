# MSRV 1.88 verification

User approved testing a lower MSRV before implementing CI. The previous 1.94
value was an initial chosen/verified baseline, not the result of a minimum-version
search. This record supersedes that active policy without rewriting old evidence.

## Change and dependency evidence

- Cargo.toml rust-version: 1.94 → 1.88; edition remains 2024.
- Cargo.lock changes only cargo-platform 0.3.3 → 0.3.2 and its registry checksum.
- No unused direct dependency, override, ignore-rust-version flag or registry
  patch. cargo_metadata 0.23.1 accepts cargo-platform 0.3.0-compatible versions.
- cargo-platform 0.3.3 inherits Cargo's workspace rust-version 1.91. Published
  0.3.2 declares 1.88. The cached registry copies of src/lib.rs, src/cfg.rs and
  src/error.rs are identical between those two releases.
- Checked all 190 locked registry-package manifests. The highest declared
  dependency requirement after the change is 1.88 (Askama, ICU and cargo-platform).
- Original package references: https://docs.rs/crate/cargo-platform/0.3.2/source/Cargo.toml
  and the local registry's 0.3.3 Cargo.toml.orig workspace inheritance.

## Observed failure and correction

After changing only our rust-version, Rust 1.88's locked all-target check failed
specifically because cargo-platform 0.3.3 requires 1.91. Ran:

```text
cargo +1.88.0 update -p cargo-platform --precise 0.3.2
```

Afterward, an ordinary `cargo +1.88.0 update -p cargo-platform` reported
"Locking 0 packages to latest Rust 1.88 compatible versions". The package's
edition-2024 MSRV-aware resolver retains a compatible version without adding an
artificial direct dependency. Use the checked-in lockfile for reproducible builds.

First MSRV test run passed 65 unit tests and 11/12 integration tests. The failing
assertion assumed all Clippy further-information URLs use a rust-X.Y path. An
isolated real 1.88 Clippy run emitted:
https://rust-lang.github.io/rust-clippy/master/index.html#clone_on_copy

The product already linked that URL correctly. Corrected the integration test
to accept the official Clippy documentation base and lint destination while
also requiring href to equal the displayed emitted URL. Existing unit tests
still verify preservation of version-specific links and rejection of unsafe
schemes. No product source change was required.

## Verified commands

Windows / PowerShell. Rust 1.88.0 (6b00bc388 2025-06-23), with its Clippy;
stable Rust 1.99.1 (58cf8f9c3 2026-10-13).

```text
rustup toolchain install 1.88.0 --profile minimal --component clippy
cargo +1.88.0 check --all-targets --locked --target-dir target/msrv-1.88
cargo +1.88.0 build --example cargo_probe --locked --target-dir target/msrv-1.88
cargo +1.88.0 test --locked --target-dir target/msrv-1.88
cargo build --example cargo_probe --locked
cargo test --locked
cargo fmt --check
cargo clippy --all-targets --locked -- -D warnings
```

All pass after the test correction. Each toolchain's suite: 65 unit + 12 actual
Clippy integration tests. The MSRV build directory is isolated from stable to
avoid stale helper/binary confusion. Integration fixtures are copied to temporary
directories; repository fixture contents were not modified.

## Limits / CI consequence

Actual compile/test verification here is Windows only. The planned CI MSRV row
should use Linux with Rust 1.88.0 and `cargo check --all-targets --locked`, alongside
stable OS test jobs. No workflow, remote repository setting, push or deployment
was created by this MSRV task. Lower versions and future dependency resolutions
are not claimed tested. UI/JavaScript code is unchanged.
