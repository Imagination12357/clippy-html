# FA-002 fixes — 2026-11-17

Original `.audit/full-audit/002/` records and scripts remain unchanged. This
records fixes for its three confirmed defects, not a new audit.

## FA-002-001: filesystem aliases on non-Windows hosts

Removed the Windows-only gate from the isolated directory-mirror check. Alias
classification now asks the actual filesystem on every platform. Unix compares
device/inode directory identity, avoiding assumptions about canonical pathname
casing. Other platforms retain canonical directory comparison. Root/ancestor
protection and probe cleanup remain in place.

Before the fix, the original platform-branch emulator reproduced external=true,
failed publication, leftover directory and rejected retry. Its source-extraction
script deliberately describes the old gated branch and is not rewritten to run
against the new implementation. The actual implementation is now unconditional;
the first-publication/retry/Unicode and ancestor-alias tests are enabled on all
platforms, conditional on the temporary filesystem's case behavior. The separate
case-sensitive external-path control remains enabled.

Local runtime evidence is Windows only. Actual macOS/Linux execution remains for
CI or a native host; no branch emulation is represented as native Unix testing.

## FA-002-003: separate Cargo build directory

Retain Cargo metadata's optional build_directory in ProjectInfo. Source loading
excludes both canonical target and build directories before reading full text, so
generated code stays snippet-only and cannot generate a suggestion patch. Older
Cargo metadata can omit build_directory; existing target exclusion still applies.
Output publication also protects the build root, just as it protects the target
root; a dedicated report below it remains allowed. Test-only ProjectInfo literals
set the new optional field explicitly.

New real-Cargo integration test first failed for the separate generated-cache.
After the fix both default and configured build-directory reports use finding
fallback anchors, have no patch and do not contain the sentinel outside the
diagnostic excerpt. The original audit probe confirms these same results.
The new build-root protection test also failed first, then passed after extending
the existing protected-root check.

## FA-002-002: first-line UTF-8 BOM

Keep raw source bytes. Only the first line's snippet/column interpretation skips
the leading BOM; byte coordinates include its three bytes. Source-row range
projection applies the same adjustment. A BOM elsewhere is not stripped.

New integration test first failed on the missing L1 link. It now checks exact
highlight text and applies the complete patch through Git, comparing output bytes
with the expected BOM-preserving LF/CRLF files. Git's user-configured autocrlf is
disabled for this test, as in the existing suggestion tests. Additional unit
coverage rejects incorrect byte offsets and stale first-line snippets and checks
that later-line offsets remain unchanged.
