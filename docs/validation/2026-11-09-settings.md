# Pinned rustdoc Settings validation

## Scope and reference

User directed a close structural port including Ayu, not a newly designed
settings screen. Started on approved local main 72a030a. Spec/mapping:
../superpowers/specs/2026-11-09-settings-design.md. Distributed provenance and
original MIT notices: ../../assets/vendor/rustdoc/SETTINGS.md. Project and font
licenses unchanged; no new production dependency or custom theme assets.

The UI keeps the pinned rustdoc 1.97.1 gear, popup/page, setting rows, radio/
checkbox structure, values, labels, order, defaults and preferred-theme visibility.
Nine applicable rows are ported; six API-only/no-target rows are omitted with
specific reasons. No new setting or Save/reset control was introduced.

## Necessary report differences

Keep the already approved unified sidebar and moving report toolbar, not the
native separate mobile topbar/source sidebar. Scoped CSS positions the popup
arrow for the two actual buttons, bounds/scrolls the original form, keeps Settings
visible on mobile and honors hide-sidebar over prior report CSS. Hide TOC targets
the existing #rustdoc-toc. Sans-serif mode retains bundled Source Code Pro.

Dark/Ayu diagnostics use translucent existing theme focus colors instead of the
strong light-yellow overlay; severity text inherits the theme foreground.
Lexical token colors and pinned rustdoc.css are unchanged. No general palette
redesign or no-op native controls.

Storage is namespaced clippy-html- to avoid changing unrelated rustdoc settings.
Denied storage falls back to current-page memory. The valid Back href defaults
to the report index; history is used only for a same-report predecessor. One-result
navigation counts all report kinds and removes the query before following it.
