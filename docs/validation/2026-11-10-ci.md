# CI validation — 2026-11-10

## Scope and execution

`.github/workflows/ci.yml` runs on PRs, main pushes and manual dispatches.
The Rust matrix tests stable on ubuntu/windows/macos-latest, and checks all
targets with Rust 1.88.0 on Ubuntu. `RUSTUP_TOOLCHAIN` also applies to Cargo
subprocesses in fixture tests. The process helper is built before tests.
Linux quality checks fmt, strict Clippy, the existing Node 24 DOM/search suite,
and the Bash dogfood behavior tests. npm/jsdom are test-only and locked.

PR and non-main manual reports run with contents:read only. Main's separate
report-pages job needs every test and quality job to succeed; it then installs
this checkout, generates one online-default self-report and publishes it in
the same job. Only this main-only job requests pages:write/id-token:write.
No pull_request_target trigger or automatic remote configuration is used.

The helper `.github/scripts/dogfood.sh` requires a fresh work directory.
CI uses RUNNER_TEMP, outside cached Cargo output. It records the commit and
toolchain, installs with `cargo install --path . --locked --debug`, and runs:

```sh
cargo clippy-html --output "$work/report" -- --locked --all-targets -- -W clippy::pedantic
```

Online category lookup may use the product's existing bundled fallback. There
is no separate offline report and no change to the product's failure policy.
`set -euo pipefail` preserves install/report exit codes through tee. Artifact
upload runs even after failure and retains report/log directories for 14 days;
installed binaries are excluded. Normal success gating prevents publication
after generation/upload/prerequisite failure. Existing Pages stays published.
Main workflows and Pages deployment are serialized; newer PR runs cancel older
PR runs. A canceled run cannot guarantee artifact upload.
