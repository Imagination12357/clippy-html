# Search implementation validation

## Reference and scope

Implemented on codex/search from 5e6bc07, following approved A1 and the user's
instruction to statically analyze generated rustdoc rather than invent its UI.
See ../superpowers/specs/2026-11-07-search-design.md for the reference hashes and
DOM/behavior correspondence, and ../../assets/vendor/rustdoc/SEARCH.md for the
distributed provenance notice.

No browser was launched. The existing local-file automation block was not
worked around. DOM parsing/execution below is not browser rendering or proof
of a particular browser's file:// resource/history behavior.

## Automated evidence

- RED: missing search-index.js made the real fixture integration test fail.
- RED: publication accepted missing/nonlocal scripts and a missing search anchor;
  the two new regression tests failed before validation was extended.
- GREEN: Cargo tests: 58 unit + 11 integration; including generated script order,
  native toolbar shell, relative assets on every page, index destinations,
  deduplicated findings, source-text isolation and script-safe JSON round-trip.
- RED: Node engine tests lacked the named engine; four tests failed before it
  was implemented. GREEN: four tests for ranking, multi-term matching, NFC,
  case/Unicode, deterministic ties, empty/no-match and uncapped totals.
- RED: DOM tests could not open native search, switch views or restore deep
  queries before search.js existed. GREEN: nine DOM tests cover view/toolbar
  movement, original DOM/focus/hash restoration, text-only results, nested URLs,
  keyboard tabs/results, 100-of-120 display limits, modifiers/editable/IME,
  500ms scheduling, Exit cancellation, missing data, rejected destinations and
  denied history. Test-only jsdom 29.1.1; no production dependency added.
- Final independent review found one Important defect: same-document sidebar
  anchors/results could leave their destination hidden. A reproducing test was
  RED before the fix and GREEN afterward, including an unchanged hash and denied
  history; a further test preserves modified clicks and the search-view skip
  link. All 13 Node tests pass. Same-document activation restores the main view
  before native anchor navigation; it strips the search parameter from the
  destination and allows native reload if history is unavailable.
- cargo fmt --check and cargo clippy --all-targets --locked -- -D warnings pass.
- Real generation: cargo run --locked -- --offline --output target/search-preview
  -- --offline --all-targets -- -W clippy::pedantic; exit 0. Staged publication
  validates generated pages, scripts, search destination files/anchors and fonts.
- The first generated-report DOM sweep checked all 35 HTML pages and all 89
  index entries (17 lints, 15 files, 56 findings, 1 category), exercising all four
  result kinds from each page. This executes scripts against parsed HTML only.
- After the anchor fix, the full Rust suite, fmt and strict Clippy passed again;
  regeneration and the same 35-page/89-entry DOM sweep passed again. Cargo's
  package list includes both search scripts and SEARCH.md with its MIT notice.

## Static UI comparison

The vendored rustdoc stylesheet is unchanged. Reused selectors include
rustdoc-toolbar, #search-button, .main-heading.search-results-main-heading,
nav.sub, .search-form, .search-input, .search-switcher, .search-out,
#search-tabs, #results, .search-results.active, .result-name, .typename,
.path and .desc. The magnifier is the existing stylesheet's SVG.

Two scoped CSS adjustments: the single report toolbar stays flex without
rustdoc's absent mobile help/settings slots, and the source input loses the
40px offset tied to rustdoc's separate source-sidebar button. Existing shared
table columns and user-approved unified file-tree alignment remain unchanged.

Report-specific differences: four report tabs; no API filters/signatures;
text-only descriptions; valid div/span content models; first nonempty tab;
stated display limit; explicit original scroll/focus restoration; optional
history; local classic scripts and an independent matching engine. Original
MIT attribution is preserved; root/Cargo and font licensing are unchanged.

Final review left no minor findings. Its explicit unjudged items are actual
pixel/responsive/font/file-URL behavior and browser focus/scroll behavior, which
remain the manual acceptance below. The reviewer inspected Rust paths/tests;
the coordinator ran the Rust suite. No browser pass is inferred from either.

## Remaining manual acceptance

Open target/search-preview/index.html directly in a browser; compare with
target/doc/cargo_clippy_html/index.html. Check Search / S / slash, typing and
Enter, all four result types, Down/Up and Left/Right, Escape/Exit, deep-query
reload, Back/Forward, source line hash/scroll restoration and modified link
clicks. Repeat from nested source/lint/category pages and at a narrow viewport.
Check JavaScript disabled and actual file:// and static-subpath hosting in the
supported browsers. No pixel/font-metric or cross-browser pass is claimed.
